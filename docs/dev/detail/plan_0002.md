# plan_0002 - Uvicorn 에러 메시지 가시성 개선 (요청 응답 실패 및 LLM API 호출 실패 원인 파악)

## User Requirements

- 서버(Uvicorn) 로그에서 요청 실패 원인을 명확하게 확인할 수 있어야 함.
- 특히 클라이언트 요청에 대한 응답 실패와 외부 LLM API(OpenAI, Gemini) 호출 실패를 구분하여 파악 가능해야 함.

## Goal

- FastAPI 전역 예외 처리기(Exception Handler)를 강화하여 상세한 에러 로그를 출력함.
- LLM Provider 호출 시 발생하는 예외를 세분화하여 로깅하고, 클라이언트에게 적절한 에러 메시지를 전달함.

## Scope

- In: `src/llm_gateway/main.py` (전역 핸들러), `src/llm_gateway/extensions/providers/` (프로바이더별 에러 처리)
- Out: 로깅 시스템(ELK 등) 구축

## Implementation Plan

- Step 1: `main.py`에 `RequestValidationError` 및 `HTTPException`에 대한 커스텀 핸들러 추가하여 요청 본문 및 상세 에러 로깅.
- Step 2: `GeminiProvider` 및 `OpenAIProvider` 내부의 `chat_complete` 메서드에 `try-except` 블록을 강화하여 API 응답 에러를 상세히 기록.
- Step 3: `logging` 설정을 조정하여 Uvicorn의 기본 출력 형식을 확장.

## Unit Test Plan (must)

- What to test: 잘못된 요청 본문 송신 시 422 에러 로깅 확인, 존재하지 않는 모델 요청 시 404 에러 로깅 확인.
- Test cases: `test_invalid_request_logging`, `test_provider_api_error_handling`.
- Command:
  - uv run pytest tests

## E2E Plan (must)

- Scenario: 잘못된 API 키를 설정한 상태에서 리모트 서버에 요청을 보냄.
- Expected: Uvicorn 로그에 "Authentication Error from OpenAI/Gemini"와 같은 명확한 원인이 출력됨.
- How to run: `bin/test-api` 실행 또는 `curl`로 잘못된 요청 전송.
- Validation: 서버 터미널의 실시간 로그(stdout) 확인.
